# Event ID 93 - Phishing Mail Detected: Excel 4.0 Macros 📧

## Short Overview of the Investigation 🔬
This investigation analyzes a high-severity phishing alert generated by LetsDefend's SOC146 detection rule. The incident involved a suspicious email containing a malicious Excel attachment, sent to an employee named Lars.

The investigation focused on analyzing the email metadata, validating the attachment's malicious nature, examining endpoint and network activity, determining whether the recipient interacted with the attachment, and recommending appropriate incident response actions.

Investigation verdict: True Positive - Malicious phishing email.

Command history also showed:

The command is consistent with an attempt to register a DLL silently. In this incident, its association with Excel-related process activity supported the assessment that the malicious document had been executed.

The browser and process evidence connected the phishing email to subsequent suspicious endpoint activity.

## My Findings, Conclusion, and Recommended Response. 🙋‍♀️
*Findings*
- A high-severity phishing alert was generated by the SOC146 detection rule.
- The email was sent from trenton@tritowncomputers.com to lars@letsdefend.io.
- The message subject was RE: Meeting Notes.
- The email was allowed through the email security control.
- The attached Excel-related file was identified as malicious by the documented analysis.
- Browser history showed a visit to a malicious domain shortly after the alert.
- Command and process history contained evidence of regsvr32.exe activity associated with an Excel document.
- The combined evidence indicated that the recipient interacted with the malicious content.

*Conclusion*
The alert was classified as a True Positive. The evidence indicates that a malicious Excel attachment was delivered to the recipient and that subsequent endpoint activity was consistent with execution of the malicious content.

The incident demonstrates why email security alerts must be correlated with endpoint and network telemetry. Blocking or delivering a message is only one part of the investigation; determining whether the recipient interacted with the payload is essential for assessing potential impact.

*Recommended Response*
1. *Contained the affected endpoint*: I isolated Lars's device from the network to limit further malicious activity.
2. *Removed the phishing email*: I deleted the message, quarantined the host message and searched for copies delivered to other recipients.
3. *Preserved evidence*: I retained the email, attachment hash, relevant logs, process history, browser history, and identified indicators.
4. *Investigated persistence and impact*: I examined process execution, DLL activity, registry changes, scheduled tasks, and other persistence mechanisms.
5. *Hunted for related activity*: I searched network and endpoint logs for the malicious domain, associated infrastructure, and related file or process indicators.
6. *Remediated the endpoint*: I removed confirmed malicious artifacts and restored the device only after verifying that it is clean.
7. *Escalate and document*: I notified the appropriate incident response team, recorded the response actions, and closed the alert only after the incident has been addressed.

## Lessons Learned 🌿

- *Email delivery does not equal safety*: A message marked as allowed can still contain a malicious payload.
- *Analyze attachments carefully*: Excel documents can be used to deliver malware and initiate further malicious activity.
- *Correlate multiple data sources*: Email metadata, threat intelligence, browser history, command history, and process telemetry provide a stronger basis for incident classification when analyzed together.
- *Investigate user interaction*: Determining whether a recipient opened or executed a malicious attachment helps establish the potential impact of a phishing incident.
- *Containment is critical*: Isolating an affected endpoint can reduce the risk of further compromise while the investigation continues.
- *Base conclusions on evidence*: A reliable SOC investigation distinguishes confirmed observations from assumptions and documents the reasoning behind its verdict.
